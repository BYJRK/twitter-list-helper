# X 列表助手

一个自用的 Chrome Manifest V3 扩展。在 X 用户主页显示该用户在你创建的列表中的归属，并通过下拉菜单添加或移除成员。

## 安装

扩展从 `dist/` 加载，该目录不提交到 Git。首次克隆仓库后，在项目根目录执行以下命令生成构建产物（需要 Node.js 20 或更新版本及 npm）：

```powershell
npm ci
npm run build
```

需要 Chrome 114 或更新版本。当前版本为 **0.2.4**，菜单使用浏览器顶层浮层，避免被 X 页面裁切。

1. 打开 Chrome 的 `chrome://extensions`。
2. 开启右上角的“开发者模式”。
3. 点击“加载已解压的扩展程序”，选择本项目的 **dist 文件夹**，不是项目根目录。
4. 刷新已经打开的 X 页面，登录后打开一个用户主页。
5. 在用户主页右上角操作栏最左侧找到列表入口。未加入时显示“未加入列表”。点击展开，点击列表项即可添加或移除。

更新代码后重新构建，在扩展管理页面点击该扩展的重新加载按钮，再刷新 X 页面。

## 功能

- 主页显示已加入的列表名称或数量。
- 时间线中悬停头像打开用户卡片，也会显示列表归属；这里只展示状态，读取失败时可以重试。
- 卡片信息与重试按钮放在原生卡片内容内部；读取失败会显示原因并提供“复制错误”。刷新后尚未捕获请求或功能开关尚未获取时，卡片保持打开则自动重试一次；关闭卡片即取消待执行的重试。
- 下拉菜单搜索列表，一键添加或移除，显示保存状态和错误。
- 点击 ☆ 将列表设为常用并置顶；设置页也可管理常用项。
- 支持私密列表标签、分页读取、站内主页切换和登录账号隔离。
- 未返回的成员状态显示 `?`，禁止操作，避免把未知状态当作未加入。
- 保存请求中断时停止进一步操作，需刷新状态确认结果。

点击浏览器工具栏中的扩展图标，或菜单底部的“设置”，可打开设置页。此扩展不创建列表：先使用 X 自带功能创建列表。

## 当前验证状态

已通过 TypeScript 类型检查、打包检查及 75 项自动化测试。自己主页的列表入口闪烁问题已修复，并由使用者在真实页面确认恢复正常；完整的登录态读写、分页和账号切换验证仍需按下文步骤完成。模拟测试不能证明当前 X 服务端仍接受这些请求。

自己主页通常只有“编辑个人资料”按钮。此前插入列表入口后，代码会因容器子元素数量变化而重新选择挂载位置，使入口在工具栏和用户名下方之间反复移动。当前判断会排除扩展自身的入口，并以回归测试验证多次页面检查后入口保持原位。

网页内部接口没有公开稳定契约。当前版本根据维护者公开的实现资料适配 `UserByScreenName`、`ListsManagementPageTimeline`、`ListAddMember` 和 `ListRemoveMember`，并优先从网页的实际请求及已加载模块获取操作 ID 和参数。模块无法获取时尝试读取已经加载的 X 脚本；仍无结果时使用资料中的基准 ID。基准 ID 可能失效。

目录与成员状态分别读取：目录使用网页列表管理页的 `ListsManagementPageTimeline`，仅传入 `count` 和分页游标。列表管理响应可能包含订阅别人的列表，因此必须按所有者 ID 筛选自己的列表；缺少所有者的记录不会用于编辑。只有符合下述部分响应处理条件时才允许跳过异常记录并展示其余有效列表，否则读取失败。通过 `/i/api/1.1/lists/memberships.json` 查询目标用户归属，指定 `filter_to_owned_lists=true`，读取完整分页后与目录合并。接口兼容性仍需在真实页面验证。

接口请求使用页面自身的登录态，优先调用 X 已加载的请求校验函数生成新的 transaction ID。此函数导出或 webpack 结构变化后，适配可能失效，可能出现 HTTP 403。错误不会被当作成功。

模块元数据中的 `featureSwitches` 和 `fieldToggles` 只声明可用参数，不代表这些参数为 true。0.1.4 修正了此前擅自启用它们的问题：优先使用原生请求中的准确值，其次读取 X 页面初始状态中的实际配置；没有实际值时要求校准，不根据参数名猜测开关。字段开关也不再自动启用。

0.1.5 对目录的部分响应单独处理：HTTP 成功、仅含代码 214 的 DecodeException、存在可识别的列表时间线且至少有一个有效自有列表时，展示已验证的自有列表，并明确提示目录可能不完整。缺少所有者的记录跳过，部分目录不会替换设置页保存的完整目录。不能据此判断错误来自推荐区；脱敏诊断新增错误路径与目录记录数量用于进一步定位。成员归属读取仍严格拒绝错误响应。

0.1.6 处理成员修改已生效但返回字段解码失败的情况：修改响应报错或缺少确认时，仅重新完整读取一次目标用户的成员归属；目标列表实际状态与操作一致才确认成功，同时更新已读取列表的勾选状态。读取失败或状态不符仍显示错误，账号、主页或缓存变化时丢弃确认。不会自动重发写请求。

0.2.1 按错误路径细化目录提示：列表 ID、名称和所有者均可验证，且解码错误仅限列表附加字段时，不显示“目录可能不完整”。缺少记录、名称、所有者或分页字段出错，以及无法定位的错误路径，仍保留提示。原始脱敏错误仍保留在诊断中；成员归属和写入确认规则不变。

0.2.4 将只读悬停查询改为直接使用 `lists/memberships.json` 的 `screen_name` 参数，完整读取分页并与自己的列表目录合并。悬停查看完全不调用用户详情接口，不依赖用户 ID 缓存或用户详情功能开关。只读缓存与主页的写入状态隔离；返回窗口时，过期或失败的卡片会重新读取。网页版登录态下的参数兼容性仍需实测；用户主页成员增删依旧按确认过的用户 ID 执行。

## 手动验证

建议用一个自己创建的测试列表，手动点击助手执行：

1. 打开一个用户主页，对比助手和 X 原生“添加/移除列表”窗口的状态。
2. 在助手中添加该用户，用原生窗口复核。
3. 在助手中移除，再用原生窗口复核。
4. 对私密列表重复上述检查。
5. 站内切换到另一用户，检查展示没有残留。
6. 检查浅色和深色主题，以及设置页中的常用列表和显示方式。
7. 打开自己的主页，确认“编辑个人资料”旁的列表入口保持稳定；切换主页标签、离开后返回，以及切回浏览器窗口后都不应闪烁。
8. 在时间线悬停用户头像，对比卡片归属与主页显示，确认卡片仅展示状态。

需要实测才能确认的内容还包括多页列表响应、账号切换、X 对请求校验的要求，以及真实页面的注入位置。

## 故障排查

- **没有列表入口**：确认当前是用户主页或主页的媒体/回复等标签，而不是帖子详情、关注者列表或首页。刷新 X 页面。
- **尚未捕获请求**：安装或更新后必须刷新页面，等 X 正常加载完成再点刷新状态。
- **接口未识别或 404**：使用 X 自带左侧导航进入“列表”页，再通过站内导航回到用户主页，点击助手“刷新状态”。这可在同一个页面上下文加载目录模块和捕获最新请求，但不保证修复所有接口变化。成员增删错误可以尝试手动打开原生“添加/移除列表”窗口，再关闭并刷新状态。
- **403**：确认正常登录且 X 自带列表功能可用。如果仍然失败，需要按当前网页请求更新适配。
- **列表接口错误**：使用 X 自带左侧导航进入“列表”页，确认原生列表是否能正常加载，再通过站内导航回到用户主页，刷新助手。仍失败时打开“查看错误详情”，点击“复制错误详情”。复制内容包含原生请求和助手请求的对照（公开操作 ID、变量类型、功能开关的实际布尔值、HTTP 状态和脱敏错误），不包含 Cookie、请求头、账号 ID、用户名称、列表名称或原始响应；不必导出 HAR。
- **`?` 状态**：该响应没有返回可确认的成员状态。保留未知，不猜测；需要检查当前响应字段。
- **保存结果未确认**：先点击刷新状态，查看真实结果，再决定是否继续操作。扩展不会自动重发写请求。
- **扩展连接失效**：在扩展管理页重新加载，再刷新 X 页面。
- **自己主页入口反复出现和消失**：已修复工具栏定位导致的闪烁。更新源码后执行 `npm run build`，在扩展管理页重新加载，再刷新 X 页面。

反馈错误时提供界面错误文字和操作步骤即可。不要发送 Cookie、Authorization 或未经脱敏的 HAR 文件。

## 开发

需要 Node.js 20 或更新版本及 npm。在项目根目录执行：

```powershell
npm ci
npm run check
```

`npm run check` 依次执行类型检查、构建和测试。可单独运行 `npm run typecheck` 或 `npm run build`。界面与页面接口层测试会读取 `dist/` 中的构建产物，因此单独测试前先执行 `npm run build`，再执行 `npm test`，避免测到旧代码。构建产物不依赖 Node.js，加载 `dist/` 即可。

提交源码、`public/`、测试和 `package-lock.json`；依赖、构建产物和本地缓存由 `.gitignore` 排除。`research/` 也在忽略规则中，目前不作为仓库文档提交。

```text
src/
  core.ts         路由、响应解析、分页与错误检查
  service.ts      列表状态、短期缓存、修改前校验
  page.ts         MAIN world 请求观察与 X 接口访问
  runtime.ts      获取 X 已加载模块中的操作和请求校验函数
  background.ts   仅接受本扩展内容脚本的请求并调用页面接口层
  content.ts      主页识别、界面与设置同步
  hover.ts        用户悬停卡片识别与只读状态展示
  ui.ts           共用样式、图标与元素创建
  layout.ts       下拉菜单的位置与视口边界计算
  users.ts        从原生响应与初始缓存提取用户身份
  diagnostics.ts 请求与响应的脱敏诊断
  types.ts        设置、快照及扩展消息类型
  page-types.ts   页面接口的 Window 全局类型声明
  options.ts      设置页
public/           Manifest、设置页和样式
tests/            核心与界面模拟测试
scripts/build.mjs 构建脚本
```

## 权限与数据

- `storage`：本地设置、账号对应的列表目录和常用项。
- `scripting`：由扩展后台调用 X 页面内的接口层，避免使用可被页面伪造的 `postMessage` 写操作通道。
- 站点权限仅限 `https://x.com/*` 和 `https://twitter.com/*`。
- 列表归属只在页面内缓存 30 秒；操作前状态超过 60 秒则要求刷新。
- 悬停卡片使用独立的只读请求。目录按账号短暂复用，成员归属按账号和用户分别缓存；关闭或切换卡片后不会显示旧请求的结果。
- 优先读取 X 原生主页响应中的用户 ID，减少额外的用户查询请求；捕获的请求变量会保留，目标用户与分页参数由助手重新指定。
- 0.2.3 同时从 X 原生时间线、用户悬停卡片响应与初始用户实体缓存读取准确的用户 ID；不再只依赖 UserByScreenName。未命中时先等待原生请求最多一秒，再尝试用户查询。账号切换会清除捕获的用户和接口配置。
- 功能开关缺失时，诊断会记录具体操作与 prepare 阶段（HTTP 状态 0 表示尚未发出请求）；不会编造布尔值，也不会再一概要求进入列表页。
- 不读取 HttpOnly 登录 Cookie、不存储凭据、不发送数据到第三方。
- 运行时仅请求 X 自身接口和已加载的 `abs.twimg.com` 脚本文件；读取脚本源用于匹配元数据，不执行下载的代码。

账号在设置页用数字 ID 区分；清除本地目录不会删除 X 上的列表或改变成员。
